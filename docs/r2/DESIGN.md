# R2 第一阶段的方法与数据约定

本实现接收 R1 的两期 SAR 影像及有效掩膜，生成新增低散射水体候选，再统计候选范围与来源建筑、道路的几何关系。它实现第一阶段的四个 R2 接口。运行命令和本次涿州结果见 [RUNBOOK.md](RUNBOOK.md)；这里解释计算依据、输出含义和适用范围。

## 输入为何先经过适配

R1 的 `prepared_inputs.json` 描述灾前、灾后影像的路径、日期、坐标与像元网格。`input_io.prepare_analysis_inputs` 将其转为 `core.PreparedInputs`，同时实际读取 TIFF，核对清单与文件。九项仿射变换只有末三项为 `[0,0,1]` 时才转为公共对象的六项形式。

两景必须是同一网格，包含相同的 CRS、宽高和像元定位。程序不在分类时自动对齐；发生不一致就报错，交由输入负责人检查。第一版的分析范围是已经交付的栅格矩形，`StudyArea` 也必须与该矩形一致。这个范围不能解释为涿州行政区或官方受灾边界。

本案例使用显式声明的 gamma0 线性功率，派生分析值为：

```text
gamma0_db = 10 × log10(gamma0_linear_power)
```

只有共同有效且线性功率大于零的像元才能转换。源文件保留，派生 TIFF 写入 gamma0、db、VV、源文件 SHA-256 与转换版本标签；`input_provenance.json` 保存来源与对象 ID 映射。原本已经是 dB 的输入不能再走线性转换入口。

转为 dB 改变了数值尺度，辐射量仍是 gamma0。当前 C1 的 `SARPreparedAsset` 固定为 sigma0/db，本地适配没有将 gamma0 改名为 sigma0，也没有修改共享 schema。`FloodRequest` 使用普通 `PreparedInputs`，因此可以承载这套明确标记的技术基线；团队对实际物理规格的接受仍需单独审阅。

## 有效观测与未知

原始预检分别检查两期自身有效性、有限数值、R1 的 0/1 掩膜和正线性功率。R1 若把源影像无效像元标为 1，程序报告输入矛盾；若 R1 主动缩小范围，则保留这项限制并记录数量。内部布尔值 `valid=True` 一律表示可以比较。

分类可进一步使用已经对齐的永久水体和排除区掩膜。显式提供的辅助资料在某处未知，或者该处属于排除区，最终输出也为未知。未提供辅助资料则保留基本规则并记录缺失，不虚构掩膜。

最终 `flood_mask.tif` 是单波段 uint8，NoData 为 255：

| 值 | 本实现的含义 |
| --- | --- |
| 1 | 满足新增低散射水体候选规则。 |
| 0 | 有效可分类，但没有满足最终候选规则；也可能是被小斑块规则删除的候选。 |
| 255 | 无法比较、辅助资料未知或显式排除，不当作已确认未受淹。 |

因此，正常的零候选结果必须有有效观测；全部未知时返回 `NO_VALID_DATA`。输入影像的负 dB 值通常是正常值，不应与 NoData 混淆。

## 候选分类规则

第一版只支持单 VV，两期共用一个有限阈值 T，严格使用小于号：

```python
pre_water = pre_db < T
post_water = post_db < T
candidate = valid & post_water & ~pre_water
```

这表示灾后低于阈值，灾前不低于阈值。灾前低散射区只是当时已有的水体候选，不能称为永久水体。等于 T 归入非水体；两期完全相同应产生零新增候选。

下面只用合成数值解释规则。假设 T 为 −18 dB，它不是涿州已校准阈值。

| 灾前 | 灾后 | 判断 |
| --- | --- | --- |
| −12 | −22 | 灾后跨入低散射类别，保留为新增候选。 |
| −25 | −23 | 两期都属于低散射类别，按灾前已有水体剔除。 |
| −5 | −12 | 虽然变弱，灾后仍未低于阈值，不属于本规则候选。 |

`post_db-pre_db` 用于检查图，不参与首版分类。显示色标的端点也不作为分类阈值。低散射会受到地表与观测条件影响，本规则不保证识别城市、植被下的所有淹水。

分类按窗口计算，随后对整张候选掩膜做四邻域连通域统计。斜角相接不连成同一斑块；最小面积为 0 时保留未经清理的基线。非零门槛只删除面积不足的候选，不填洞、不扩张、不跨未知区连接。全局清理避免把跨窗口的大斑块误当成若干小斑块删除。

## 参数比较与验证

`thresholds.evaluate_candidates` 对每个配置使用相同输入和相同开发区。分类与斑块清理先在完整网格运行，再限制统计范围；裁剪开发区不会改变跨边界斑块的保留条件。公共 `evaluate_flood_thresholds` 保留原签名，默认统计完整输入；需要开发区时由案例入口显式调用私有区域参数，不能把全区统计称作留出验证。

没有参考标签时，Precision、Recall、F1 和 IoU 均为 null，报告为 warning。`selected_options` 按配置候选顺序采用第 0 项作为试运行参数，不能据此称其最优。报告保存候选顺序、面积、碎斑情况和选择说明。

参考栅格必须同网格，声明 `target=new_flood` 和匹配的前后日期，取值 1、0、255 分别表示目标、非目标与未知。灾后全部水面不能直接当成新增洪水标签。指标只在双方共同有效位置计算，分母为零返回 null。开发区可用于选择参数；最终验证需使用未参与选择的区域，并核查资料的独立性。与另一套同源 SAR 产品相符，只能说明产品一致性。

## 从像元到面

`vectorization.polygonize_mask` 仅对类别 1 转面，保留像元边界和洞，不作几何简化。分析产物是 `flood_polygons.gpkg` 的 `flood_polygons` 图层，保存 `candidate_id`、事件、运行、方法、像元数和平方米面积。`candidate_id` 只在本次运行内稳定。

需要修复几何时记录原因与面积变化，并检查修复结果是否仍由面组成。`verify_vector_mask` 将面重新栅格化，核对候选位置、像元数与面积。`flood_polygons.geojson` 是 EPSG:4326 的展示副本；面积字段仍来自分析投影，不以经纬度直接计算面积。零候选也输出合法空图层。

## 建筑与道路如何统计

`summarize_exposure` 从最终掩膜的 `mask != 255` 建立可观察范围，用空间索引找可能相交的对象，再精确计算交集。同一对象命中多个候选面时，先合并交集再求面积或长度，不按连接结果的行数计数。

来源记录必须说明稳定 ID 字段。OSM 来源键应保留类型，例如 `way:123` 与 `relation:123` 是不同来源对象。同 ID 同几何记录去重；同 ID 不同几何直接报 `DUPLICATE_ID_CONFLICT`，等待数据负责人确认。无效、空或缺失几何不自动冒充可定位对象，原因写入 `exposure_geometry_issues.csv`。不同 ID 仍可能对应同一实体，因此建筑数量称为来源建筑对象数。

建筑逐对象保存总面积、已观察面积、候选交叠面积、覆盖状态和三值 `candidate_exposed`：

| 覆盖与交叠 | candidate_exposed | 比例说明 |
| --- | --- | --- |
| 完整观察且有正面积交叠 | true | 可给总面积比例与已观察面积比例。 |
| 完整观察且无正面积交叠 | false | 两项比例为 0。 |
| 部分观察且已发现交叠 | true | 总面积比例为 null，只给已观察部分比例。 |
| 部分观察但未发现交叠 | null | 未观察部分无法判断，总面积比例仍为 null。 |
| 完全未观察 | null | 交叠面积及两项比例均为 null。 |

仅边界接触的面积为 0。面积容差为 1e-6 m²，完整覆盖判断另使用 1e-9 的相对容差，均写入元数据。`outside_raster_area_m2` 与 `unknown_within_raster_area_m2` 分开表示图像范围外面积和范围内未知面积。

道路使用相同覆盖逻辑，计算的是精确交集长度，点接触长度为 0。字段对应 `road_length_m`、`observed_length_m` 和 `candidate_overlap_length_m`，另记录图外与图内未知长度。候选范围涉及道路不等于道路已经阻断。

汇总中的建筑交叠面积是各个不同来源 ID 的交叠面积之和，不是跨建筑去重后的地理面积。缺层指标为 null；合法空图层可以得到已知的 0；全部对象未观察时交叠汇总为 null。人口统计首版未实现，`population_exposed` 保持 null。

## 交付给下游的文件

| 文件 | 用途 |
| --- | --- |
| `flood_result.json`、`metadata.json` | 公共结果对象、输入、方法与参数。 |
| `flood_mask.tif`、`flood_polygons.gpkg` | 分类与分析用面。 |
| `exposure_features.gpkg` | `buildings`、`roads` 两个正式明细图层。 |
| `exposure_buildings.csv`、`exposure_roads.csv` | 不含几何的逐对象明细；null 写为空字段。 |
| `exposure.csv`、`exposure_report.json` | 指标、单位、来源和警告；JSON 保留 null。 |
| `exposure_qa.json`、`exposure_geometry_issues.csv` | 来源去重、不可用几何与覆盖检查。 |
| `validation/` 内检查报告 | 栅格、转面和实际文件的一致性证据。 |

软件检查通过只说明这些约定和计算实现通过测试。真实输入运行完成说明能够生成可复跑的候选与统计；科学精度还需要合适参考资料。当前不存在参考时，不将候选面积写成已确认洪水面积，也不将来源建筑交叠数写成建筑损毁数。
