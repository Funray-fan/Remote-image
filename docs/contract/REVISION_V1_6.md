# v1.6 修订与代码同步状态

本轮保留 v1.5 历史文件，并将 v1.6 新增接口发布为机器契约 2.0。公共 dataclass、六个岗位模块的函数骨架、`schemas/v2`、合成正反 fixture、序列化与语义校验已经同步。无业务实现的函数明确抛出 `NotImplementedError`，不会伪装成已有算法成果。

| 修改点 | 目标行为 | 主责与迁移 |
|---|---|---|
| 数据前提 | 同事件优先；缺高分光学可用xBD独立事件验证，明确event_id | R1建立清单，C2确认输入规格 |
| SAR处理 | 按产品状态处理后交付sigma0_db；前后阈值、极化组合和排除掩膜明确 | R1/R2提供schema与样例，C1迁移 |
| 灾损出口 | 一个建筑灾损模型；逐建筑damage_vector必需，mask可选；C2负责聚合 | C2给ModelInputSpec、版本和聚合规则 |
| 数据划分 | 原始场景/影像对分组，检查空间重叠 | C2评估报告，R1协助整理 |
| 正射双入口 | 原始重叠航片离线摄影测量；已有正射直接登记 | R3主责工具与QA，R1整理，C1包装支持 |
| 核查闭环 | 有限建筑/道路抽样→人填写→QA→道路状态更新→重算 | R2核查，R3更新与寻路，C1编排 |
| 路线约束 | 确认阻断排除；未知可排除或加成本，不能标为安全 | R3给RouteOptions与反例测试 |
| 区域排序 | 固定1km网格；灾损、人口、不可达分项；缺失为null，逐格重归一化并显示覆盖率 | R3给PrioritySpec及可复核样例 |
| 接口断点 | MapLayerSpec→LayerManifest；rank_priority_areas显式接RouteResult；模型名+版本 | 各owner给样例，C1集成 |
| 展示与比较 | 核查前后同端点/参数比较，展示未知与无收益情形 | C1汇总，C3显示 |

已完成：对象字段/枚举与空值规则 → v2 schema 和合成正反样例 → Python 对象与适配器边界 → CI 漂移检查。待各岗位完成：遥感/GIS/模型业务实现 → 阶段编排与 UI → 科学效果和人工演示验收。每个后续不兼容变更须提升机器契约版本并给出迁移说明；文档版本号不能替代 schema 版本号。

验收分两层：工程门槛（对象、CRS、产物、复跑）可先定；科学效果由baseline支撑，owner提议目标，项目组在继续调优与最终测试前确认，不虚构精度。
